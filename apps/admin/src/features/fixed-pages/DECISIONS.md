# 固定ページの中身とフォーム

- フォームの最上位の段・group・repeat の各要素は、それぞれの段で、項目の値と、定義に無いキーの値を分けて持つ。server は中身を丸ごと置き換えるので、定義に無いキーも元の段に戻して送る。キーと値の組から `Object.fromEntries` でオブジェクトを作り、`__proto__` もその名前のキーとして扱う。
- text・longText・url の未入力は空の文字列、number・boolean・date・select の未入力は `null` にする。これで `0` や `false` も入力した値として扱える。新しい固定ページでは、必須の boolean は `false` から始める。
- 保存した中身の値は、contract のスキーマと select の選択肢で確かめる。値が無いときや定義と食い違うときは未入力に戻し、必須の boolean でも保存した値を推測しない。object でない repeat の要素も位置を保ち、管理者がその場所で直せるようにする。
- 送るときは未入力の項目のキーを省き、必須かどうかの検査は server に任せる。必須の group は空でも送り、内側の項目に issue が付くようにする。必須の repeat は要素が無ければ空の配列を送る。任意の group を送るのは、内側に入力した値・repeat の要素・定義に無いキーのいずれかがあるときだけ。必須の boolean の `false` は入力に数えない。内側の必須の group・repeat が空であることだけでは、外側の group を入力したことにはしない。
- repeat の要素にはフォームを作るときに `crypto.randomUUID()` で ID を付ける。要素を動かしても値と ID は一緒に動き、保存には値だけを使う。issue の添え字は送ったときの並びで ID に読み替える。値を持つ項目・group・repeat・repeat の要素までたどれた issue はその場所に結びつけ、結べない issue は `unbound` として別に返し、画面がフォーム全体の誤りとして出せるようにする。

- TanStack Form には、入力値と repeat の ID の並びを別々に持たせる。場所には項目のキーと要素の ID を `/` でつないで使う。これで再帰する項目名の型を作らずに済み、並べ替えても入力・誤りの知らせ・touched は同じ要素に残る。
- 並べ替えのボタンは端に着いて無効になっても focus を受け取れるようにし、続けて操作する利用者に移動先を知らせる。削除後は次の要素の削除ボタン、末尾なら追加ボタンに focus を移す。
- 保存中は入力と並べ替えを一時止める。作成後の画面遷移で、送信後に加えた変更が失われることを防ぐ。

## 割り切ったこと

- 任意の group・repeat を空のまま保存してあった固定ページは、保存し直すとそのキーが消える。フォームではどちらも未入力として扱うので、空で保存されていたかを別に持つ理由が無い。
- 任意の group の中身が必須の boolean の `false` だけで保存されていた場合、保存し直すと group ごと省かれる。フォームは初期値のままの `false` と選んだ `false` を区別しない。
- 保存した中身に無い項目も、フォームを作るときは値のスキーマで検査する(`safeParse(undefined)`)。repeat が1万要素あり、各要素に任意の項目が100個ある中身では、フォームを作る時間が約100ms 伸びる(Bun で計測)。個人サイトの固定ページの repeat はそこまで増えず、フォームを作るのは開くときの1回だけなので、受け入れる。
