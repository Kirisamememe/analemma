## 見る範囲

管理画面(`apps/admin`)を使う管理者にとっての、操作の分かりやすさとアクセシビリティ。コードを読んで分かる範囲で見る。

- 操作の流れ:今どの状態か(読み込み中・空・失敗・送信中)が見えるか。失敗したときに、何が起きて次に何をすればよいかが分かるか。取り消せない操作の前に確かめるか。送信中に、同じ操作を続けて送れないようにしているか。
- 入力:検証の結果が、どの入力欄の何についてかと一緒に伝わるか。入力した内容が、失敗や画面の移動で黙って消えないか。
- キーボード:すべての操作がキーボードでできるか。フォーカスの順と移り方(ダイアログを開いたとき・閉じたとき、画面を移ったとき)が自然か。フォーカスが見えるか。
- 支援技術:accessible name、role、状態(`aria-expanded` など)、見出しの順、landmark、状態の変化の読み上げ(live region)が合っているか。ネイティブの要素で済むところに、独自の要素を使っていないか。
- 見え方:文字と背景のコントラスト、色だけに頼った区別、`prefers-reduced-motion`、拡大したときのはみ出しや重なり。
- 管理者に見える文言が、操作の結果と合っているか。

## 見ない範囲

- 見た目の好み(配色・余白の大きさ・フォント)と、スタイリングやデザインシステムの選び方。まだ決めていないので、提案しない。
- 対象は最新の Chrome と WebKit だけ。古いブラウザへの対応は指摘しない。Firefox にも必要以上に合わせない。Baseline で newly available になったばかりの CSS・HTML・JS の API は使ってよい。
- 表示の裏のロジックの正しさ(ビジネスロジックの観点)と、認証や入力の境界(セキュリティの観点)。
- 書き方・フォルダ・文書の置き場所などの、リポジトリの約束(規約やルールの遵守の観点)。
- 文言の日本語としての自然さと、用語集に従っているか(言葉の観点)。
