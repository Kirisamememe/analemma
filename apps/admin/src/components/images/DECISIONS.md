# 画像を選ぶ Dialog

- 写真の配置、続きを読み込む操作、取得に失敗したときの再試行は画像の一覧と共有する。Dialog は別の query のキーを使い、画像の画面に戻るために保持するページとスクロール位置に影響させない。
- 1枚を選ぶときはラジオボタン、複数枚ならチェックボックスで写真を選ぶ。追加済みの画像は選択数に含めない。選択を確定した時点で呼び出し元に画像を渡すので、キャンセルで編集中の値を保てる。

- 表紙を選び直すときは現在の画像で選択を始め、フッターに選択中のタイトルを表示する。現在の表紙が Dialog を開いた後に届いたときは、未操作なら初期値として表示し、すでに選び直した写真は保持する。写真全体を見比べられるよう、1枚を選ぶ一覧では元の縦横比を使い、選択の印を写真に重ねる。

## 変換中の画像

- 写真は、受け取りと変換が別に進む。一覧と写真の画面は、画像の状態(変換中・変換できなかった理由・非公開・公開)から、バッジと、写真の場所に出す文言を決める(`logic/image-status.ts`)。変換できなかった画像は、理由(写真を読めない・server の都合)を写真の場所に書き、送り直して直るかどうかを伝える。
- 変換が終わったことは、変換中の画像を取り直して知る(`hooks/use-image.ts`。2秒おき)。一覧は、読み込んだ変換中の画像のうち、いちばん先に受け取った1枚だけを取り直し(`hooks/use-conversion-watch.ts`)、一覧そのものは読み直さない。server は変換を1枚ずつ進めるので、たいていはその1枚が次に終わる。並べて送った写真は順が入れ替わることがあり、そのときは、後の写真の結果が出るのが、先の写真が終わるまで遅れる。変換中の画像が無ければ、何も取り直さない。
- 取り直しに失敗しても、取得できるまで取り直し続ける。止めると、通信が戻っても一覧が変換中のまま残る。取り直した画像が無くなっていたら(別のタブで消したなど)、読み込んだ一覧から外して、次の変換中の画像へ進む。
- 取り直した画像が変換を終えていたら、読み込んだ一覧のその画像の、状態・公開した日時・配信用の画像だけを差し替える。変換中のままなら、一覧のキャッシュに触れない。タイトルや説明は差し替えない。保存の応答より遅れて届いた取り直しの結果が、保存した値を古い値に戻さないようにする。
- 写真の画面は、状態のバッジと、写真の場所に出す文言を `output` に入れ、変換の結果を読み上げにも知らせる。

## 再レンダリングの期待

頻繁に変わる state は、画像の選択と、変換中の画像の取り直し(2秒おき)。件数に比例して増える部品は、一覧のタイル。

- 選択状態は Dialog を開いている間だけ保持する。入力欄は自分の画像が選ばれているかを、フッターは、選択中の画像のうち、追加済みと削除済みを除いた枚数を購読する。1枚を選択・解除しても、ほかのタイルと Dialog を再レンダリングしない(`hooks/__tests__/use-image-choice.test.tsx`)。

- 変換中の画像を取り直している間は、一覧もタイルも再レンダリングしない。取り直しを購読するのは、何も描かない部品(`ConversionWatch`)だけにする。変換を終えたときは、その画像のタイルだけを再レンダリングする(`__tests__/images-section.test.tsx`)。
