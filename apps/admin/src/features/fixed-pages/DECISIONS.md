# 固定ページの中身とフォームの値

- 根・group・repeat の各要素は、その段の項目の値と、定義に無いキーの値を分けて持つ。server は中身を丸ごと置き換えるので、定義に無いキーも元の段に戻して送る。キーと値の組から `Object.fromEntries` でオブジェクトを作り、`__proto__` もその名前のキーとして扱う。
- text・longText・url の未入力は空の文字列、number・boolean・date・select の未入力は `null` にする。これで `0` や `false` も入力した値として扱える。新しい固定ページでは、必須の boolean は `false` から始める。
- 保存値は contract のスキーマと select の選択肢で確かめる。値が無いときや定義と食い違うときは未入力に戻し、必須の boolean でも保存値を推測しない。object でない repeat の要素も位置を保ち、管理者がその場所で直せるようにする。
- 送るときは未入力の項目のキーを省き、必須かどうかの検査は server に任せる。必須の group は空でも送り、内側の項目に issue が付くようにする。必須の repeat は要素が無ければ空の配列を送る。任意の group を送るのは、内側に入力した値・repeat の要素・定義に無いキーのいずれかがあるときだけ。内側の必須の group・repeat が空であることだけでは、外側の group を入力したことにはしない。
- repeat の要素にはフォームを作るときに `crypto.randomUUID()` で ID を付ける。要素を動かしても値と ID は一緒に動き、保存には値だけを使う。issue の添え字は送ったときの並びで ID に読み替える。項目・group・repeat・要素までたどれた issue はその場所に結び、たどれないものもフォーム全体で扱えるように返す。

## 割り切ったこと

- 任意の group・repeat を空のまま保存してあった固定ページは、保存し直すとそのキーが消える。フォームではどちらも未入力として扱うので、空で保存されていたかを別に持つ理由が無い。
