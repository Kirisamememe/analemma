# 決めたことと理由(series の feature)

- シリーズと画像は多対多で、`series_image` にシリーズごとの位置を持つ。シリーズと画像の ID を合わせた主キーで、同じシリーズに同じ画像が重なるのを防ぐ。
- 公開状態は `publishedAt` の有無で持ち、シリーズは物理削除する。シリーズと画像のどちらを消しても、関係する行は FK の cascade で消える。片方を非公開にしても、もう片方の公開状態と画像の並びを保つ。
- 名前・slug・説明の書き換えでは、ほかのシリーズに使われていない slug かを確かめてから書き、使われていれば `SLUG_TAKEN` で断る。作成の重なりは `ON CONFLICT DO NOTHING` で `SLUG_TAKEN` にする。
- 管理用の一覧と取得は、非公開の画像も配信用の URL と一緒に返す。画像の公開状態は、シリーズから外すことなく管理画面で確認できる。

## 割り切ったこと

- **書き換えの slug の競合**:同時に2つのシリーズを同じ slug に書き換えると、後の方が一意の制約で失敗し、500 とログになる(固定ページと同じ)。管理者は1人で、ミリ秒の差で同じ slug を2つのシリーズに付けることはまず無い。防ぐためにシリーズの表全体をロックすると、説明だけの保存でも、ほかのシリーズの作成や公開を待たせる。
