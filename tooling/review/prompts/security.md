## 見る範囲

外から悪用できる穴と、守りの抜け。

- 認証:パスキー・セッション・再認証・登録用 URL。資格情報の無いリクエストや、ほかの管理者のセッションで通らないか。
- 認可:procedure が、アクセス区分に合った base から作られているか。アクセス区分の外から呼べる procedure や route が無いか。
- 入口の守り:外部用のポートと内部用のポートの分け方、CSRF・Origin の確認・secureHeaders・no-store。守りを掛けるべき route から外れていないか。
- 入力の境界:zod での検証、大きさ・数・深さの上限、パスや URL の組み立て、SQL・HTML・シェルに渡す値。
- 秘密の扱い:トークンや資格情報が、ログ・例外の文・応答・URL・コミットするファイルに出ないか。比べ方から、タイミング攻撃で漏れないか(定数時間で比べているか)。
- 情報の露出:公開していないコンテンツや、ほかの管理者の情報が、応答やエラーの文から見えないか。
- CI と依存:workflow の `permissions`、外から来る値の渡し方(script injection)、actions の固定、install で流れる script。

## 見ない範囲

- 悪用につながらない、仕様どおりかどうかの誤り(ビジネスロジックの観点)。
- 管理画面の見た目・操作・アクセシビリティ(UI/UX とアクセシビリティの観点)。
- 書き方・フォルダ・文書の置き場所などの、リポジトリの約束(規約やルールの遵守の観点)。
- 文書・コメント・テストの名前・管理画面の文言の言葉(言葉の観点)。

## 重要度の目安

- 資格情報無しで、外から悪用できるなら高。
- 管理者の資格情報が要る、または条件が重なったときだけ起きるなら中か低。
- 細工した入力でだけ起き、500 とログで済み、データも漏れないなら実害無し。
