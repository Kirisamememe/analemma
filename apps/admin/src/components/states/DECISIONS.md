# 決めたことと理由(読み込めなかった欄)

読み込めなかったことと次にすることを伝え、取り直せる欄(`ui/error-state.tsx` の `ErrorState`)。文面を自分で持つので、デザインシステム(`src/ui/`)ではなく、ここに置く(`apps/admin/DECISIONS.md` の「業務の知識を足す層」)。

- **見た目と文面**:読み込めなかったことを見出しで、次にすることを補足で伝え、「もう一度試す」のボタンを置く。並びと大きさは中身の無い欄と同じにし、点線でなく実線の枠と、`danger` の薄い丸(`danger/10`)の雲のアイコンで、空とは見分ける。一覧の中(`inline`)では枠を付け、画面の中身の全体(`screen`)では枠を付けない(区切る相手が無い)。見出しのレベルは、置く場所の見出しの次のレベルを呼び出し側が渡す。何を読み込めなかったか(見出し)は feature が渡す。最初の補足は、画面に合わせた文(種類の定義を読めないときなど)を feature が渡せ、渡さなければ部品の文(接続を確かめてから試し直すこと)を出す。取り直しも失敗した後の2文と、ボタンの文言は部品が持ち、どの画面でも同じにする。
- **取り直し**:見出しと補足を `alert` にまとめ、出たときに読み上げる。取り直している間は、ボタンを送信中にし、focus を残す。取り直しも失敗したら、補足を「まだ読み込めません。」と次にすることの2文に替え、`alert` の要素を作り直して読み上げ直す。3回目からは文が同じなので、作り直さないと読み上げられない。失敗したかは、描いている間に「取り直しているか」が true から false に変わった回数で数える(取れたら、呼び出し側がこの欄を描かない)。画面が隠れて、次の試行を待って一時停止している間も、取り直していることにする(一時停止を失敗と数えない)。2文は別の行にし、補足の行の長さを `text-balance` でそろえる。1つの文にすると、狭い画面で「時間をおいて」の途中で折り返した。取り直せた後は、一覧やフォームの全体に focus を移さない。次に操作するものを示す枠が、欄の全体を囲んでしまうため。

## 再レンダリングの期待

頻繁に変わる state も、件数に比例して増える部品も無い。state は、取り直しが終わった回数だけで、取り直しのボタンを押して、応答が届いたときに変わる。

## 割り切ったこと

無し。
