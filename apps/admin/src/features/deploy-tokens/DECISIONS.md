# 決めたことと理由(管理画面の deploy-tokens の feature)

画面は `/deploy-tokens`(デプロイ用のトークン)。一覧と、発行・取り消しの操作を置く。server の決まりは `apps/server/src/features/deploy-tokens/DECISIONS.md` にある。

## 発行

- 発行の前に再認証をする(server の決まり)。再認証をキャンセルしたら、発行を送らない。
- 名前は、再認証の前に、contract と同じスキーマ(`deployTokenName`)で確かめ、入力欄に誤りを出す。送ってから server に名前を断られると、再認証の OS の画面を済ませた後に、想定外の失敗として知らせることになる。
- token は、発行した Dialog の state にだけ置き、TanStack Query(query と送信の cache)に入れない。送信の結果に token を入れると、Dialog を閉じても、送信の cache が消えるまで(既定で5分)query client から読める。送信の結果は、どの結果か(`_tag`)だけにする。一覧は server が token を返さず、URL にも載せない。閉じた後に、画面・URL・query client のどこからも token を読めないことを、画面のテストで確かめる。
- 発行できたら、同じ Dialog を、token を見せる中身に替える。Dialog を閉じると、token はもう出せない。発行したことは、その Dialog を閉じたときに Toast で知らせる。token を見せている間に Toast を出すと、Toast の出入りの View Transition が始まって新しい DOM を描くまでの間(普段は1フレームほど)は、押した操作が document の要素に当たり、React Aria Components が Dialog の外側の押下とみなして閉じる。「コピー」を押したつもりで token を失うので、見せている間は Toast を出さない。
- token は、ラベルを付けた読み取り専用の textarea に等幅の字体で出し、focus したら全体を選ぶ(`ui/token-value.tsx`)。コピーできなかったときも、キーボードで欄に移って手でコピーできる。中身を替えたら、コピーのボタンに focus を移す。押したボタンが消え、focus の行き先が無くなるため。
- コピーのボタンは Clipboard API で書き、結果を、ボタンの文言とアイコンで返す(`ui/copy-button.tsx`)。`Notice` は使わない(ユーザーが決めた)。押したボタンだけにかかわる結果なので、ボタンの上で返す。Toast も使わない。token を見せている Dialog の上で Toast を出すと、上に書いた View Transition の始まりの押下で、Dialog が閉じうる。
- コピーできたら「コピーしました」とチェックのアイコンを2秒出してから「コピー」に戻し、書けなければ(許可が無いなど)「コピーできませんでした」を押し直すまで残す。書けなかったときは手でコピーする必要があり、知らせが消えると、コピーできたように見える。文言が替わってもボタンの幅を変えないよう、3つの文言を重ねて置き、見せないものを隠す。幅が変わると、隣の「閉じる」が動き、狭い画面や拡大で列が折り返すと、「閉じる」がコピーのボタンのあった位置に来て、押し直すつもりで Dialog を閉じ、token を失う。ふだんのボタンは一番長い「コピーできませんでした」の幅になるが、押す位置が変わらないことを取る。結果は、ボタンの外の `status` の領域でも読み上げ、書けなかったときは、手でコピーするよう伝える。focus したままのボタンの名前が替わっても、スクリーンリーダーが読み直すとは限らない。
- 文言を戻す timer は、押したときの handler で始め、effect を使わない(`apps/admin/DECISIONS.md` の「React の effect」の、操作がきっかけの処理)。Dialog を閉じて部品が消えた後に timer が来ても、React は消えた部品の state の更新を捨てるので、片付けは要らない。2秒のうちに押し直したときは、前の timer が新しい結果を消さないよう、timer を始めた押下の結果がまだそのまま出ているときだけ戻す(結果は押すたびに別の値として持ち、値が同じものかで比べる)。
- 発行のロジック(再認証して発行し、token を Dialog の state にだけ持ち、閉じるときに発行を Toast で知らせる)は `issue/use-issue-deploy-token.ts`、コピーは `issue/use-copy-text.ts` に置き、発行の Dialog はマークアップと、それをロジックにつなぐコードだけにする。
- 一覧は、発行できたときだけ取り直す。断られた発行は、一覧を変えない。

## 取り消し

- 取り消しには再認証を求めない(server の決まり)。取り消したトークンは元に戻せないので、トークンの名前を出した確認の Dialog の後に送る。
- 取り消しを送った後は、もう無いトークン(`NOT_FOUND`)と答えられても一覧を取り直す。Dialog と一覧の focus の扱いは、パスキーの欄と同じ(`apps/admin/DECISIONS.md` の「パスキーとセッションの管理」)。行が消えたら、欄の最初の要素(トークンの発行のボタン)に focus を移す。

## 作り物の server

- `src/testing/fake-routes/create-deploy-token-routes.ts` は、セッションの取得(`admin/session/get`。いつもセッションがあると答える)と再認証の options の応答も自分で持つ。パスキーの作り物とは別に、この画面のテストと story だけで使う。1つの再認証で1回だけ発行でき、無いトークンの取り消しは `NOT_FOUND` を返す。

## 割り切ったこと

- **発行の応答を待つ間に画面を離れたとき**:再認証を済ませてから発行の応答が届くまでの間に、履歴でほかの画面へ移ると、発行の Dialog が取り除かれ、届いた token を見せられない(トークンは一覧に残り、Toast も出る)。再認証の OS の画面を開いている間は画面を操作できず、その後の応答は普段は数十ミリ秒で届く。止めるには、送っている間の履歴の移動を止める仕組みを `src/api/` に足す必要がある。起きても、そのトークンを取り消して発行し直せば済むので受け入れる。
- **コピーの前に閉じられる**:token を見せている Dialog も、ほかの Dialog と同じく、Escape・外側の押下・「閉じる」で、確かめずに閉じる。コピーの前に閉じると、token はもう出せない。一度だけ見せることは、中身の先頭の知らせで伝える。閉じても、そのトークンを取り消して発行し直せば済むので、閉じる前に確かめる手順は足さない。
- **取り消しの後の一覧の取り直し**:取り消しの応答が届いた後も、一覧を取り直し終えるまで、Dialog は送っている間のまま(閉じられず、Toast も出ない)。パスキーの Dialog と同じく、取り直してから閉じる(`apps/admin/DECISIONS.md` の「features の依存」の `useApiMutation`)。一覧の取得が遅いときだけ待たされるので受け入れる。
- **ほかのタブでのログアウト**:token を見せている間に、同じブラウザのほかのタブで(すべてのセッションから)ログアウトしても、このタブは token を見せ続ける。ログアウトをタブをまたいで知らせるには、BroadcastChannel を購読する effect の hook が要る。見えるのは token を発行した管理者の画面で、ログアウトした後もそのタブを開いたまま人に渡すときだけ困る。漏れたら取り消せばよいので受け入れる。
- **取り消しの確認に遅れて届く click**:`src/ui/DECISIONS.md` の「閉じ始めた Dialog に遅れて届く click」と同じ条件(タッチの長押しから80ms のうちに Escape か backdrop で閉じる)で、取り消しが送られる。取り消しは再認証を求めないので、再認証の OS の画面でも止まらない。起きる条件が狭く、取り消されても発行し直せば済むので受け入れる。
- **閉じた後の Dialog の state**:発行した Dialog を閉じても、次にどちらかの Dialog を開くか、画面を離れるまで、token は Dialog の state(メモリ)に残る。閉じるときに消すと、閉じる animation の間に中身が名前の入力に戻って跳ぶ。DOM と query client には残らず、読めるのは開発者ツールで React の state を見る人だけで、その人はすでに管理者のセッションを持つ。
- **Toast の出入りと重なった押下**:Toast が出るときと消えるときの View Transition が始まってから新しい DOM を描くまで(普段は1フレームほど)の押下は、document の要素に当たり、React Aria Components が開いている Dialog の外側の押下とみなして閉じる。token を見せている Dialog が閉じると、token はもう出せない。発行の Toast は Dialog を閉じるまで出さないので、起きるのは、ほかの操作の Toast(5秒で消える取り消しの `success` など)が、token を見せている間に出入りする瞬間と押下が重なったときだけ。失っても、そのトークンを取り消して発行し直せば済む。直すには Toast の部品で View Transition の間の押下を扱う作りが要るので、受け入れる(ユーザーが決めた)。
