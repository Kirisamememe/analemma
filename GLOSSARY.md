# 用語集

読み違えると困る語と、このリポジトリの大事な概念の名前だけを載せる。どちらで書いても伝わる言い換え(フォルダとディレクトリ、ワークスペースとパッケージなど)は載せない。上から、読み違えたときに困る順に並べる。理由は `DECISIONS.md` の「用語集」にある。

## 書かない語

- 日本語の慣習に合わない造語を書かない。
- 英語の語は英語のまま書く。仕様・ライブラリ・CSS・JS でよく使う語(options・padding・margin・challenge など)は訳さない。訳すのは、日本語の技術文書で定着した訳語(「公開鍵」「署名」「許可リスト」「判別共用体」「ブランド型」など)があるときだけ。自分で直訳した語は、定着した訳語ではない。
- これまでに書かれた造語と、代わりに書くもの:「配送役」→ dispatcher、「正規のパス」→ canonical URL、「判別子」→ `_tag`、「外向き」→ outbound、「ログの書き出し口」→ logger、「実装の元」→ base、「基盤の層」→ `src/platform/`、「選択肢」(WebAuthn の options)→ options(select の項目の `options` は、select の選択肢として定着した言い方なので「選択肢」と書く)、「埋め草」→ padding、「方式」(algorithm)→ アルゴリズム、「署名の回数」→ `signCount`。
- 「印」「札」(「目印」「名札」も)を、何かを指す比喩に使わない(「印を付けた型」「札を貼る」など)。指しているもの(プロパティの名前、値、型、`_tag` など)をそのまま書く。「消印」「札幌」のような、ものをそのまま指す語は使ってよい。
- ソフトウェアのバージョンを「版」と呼ばない(「版を上げる」「drizzle-orm の版」など)。「安定版」「Debian 版」のような、日本語で定着した使い方は使ってよい。

## 取り違えると困る語

このリポジトリの中で、意味が分かれる語。どの意味かを書き分ける。

| 語               | 書き分け方                                                                                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| feature          | server のコードを、扱う物事ごとに縦に分けた単位(`src/features/<名前>/`)。「機能」と呼ばない。                                                                  |
| 公開             | コンテンツを公開サイトに見せること(公開状態)と、公開 API・公開サイトにだけ使う。コードの export を「公開」と呼ばない。                                         |
| スキーマ         | zod のスキーマを指す。Drizzle で書いた DB の形は「テーブル定義」、PostgreSQL の名前空間(`drizzle` など)は「PostgreSQL のスキーマ」と書く。                     |
| PostgreSQL と DB | 「開発用の PostgreSQL」(`postgres`)、「テスト用の PostgreSQL」(`postgres-test`)、その中の「テンプレート」と「テストの DB」を書き分ける。                       |
| テンプレート     | migration を適用した、テストの DB を作る元になる DB を指す。JS の文字列は「テンプレートリテラル」と書く。                                                      |
| ユーザー         | このリポジトリの持ち主(エージェントに作業を頼む人)を指す。CMS を使う人は「管理者」(管理画面を使う人)か「利用者」と書く。                                       |
| ロール           | PostgreSQL のロールを指す。誰が呼べるかによる `public`・`auth`・`deploy`・`admin` の分け方は「アクセス区分」と書き、「区分」と略さない。                       |
| 種類             | 固定ページの種類(`kind`)だけを指す。ほかの意味には使わず、言い換える(`_tag` は「どの結果か」、COSE の kty は「鍵の型」、lint のルールは「ルールの分類」など)。 |
| 項目             | 種類の中の、値の定義の1つ(`fields` の1つ)だけを指す。`key` は「項目のキー」、`label` は「ラベル」と書く。TypeScript の型の property は「プロパティ」と書く。   |
| イベント         | コンテンツの変更から導く出来事は「ビジネスイベント」と書き、「イベント」と略さない。                                                                           |
| 診断             | lint や検査が報告する、ルールに合わないことの1件。「指摘」はレビューの指摘にだけ使う。                                                                         |
| 例外             | lint の抑制を「例外」と呼ばない(800行まで許すものは「理由付きの抑制」)。throw する失敗は「想定外の失敗」と書く。                                               |
| フロントエンド   | 公開サイトと管理画面を「フロントエンド」と呼ばない。どちらかを書く。                                                                                           |

## このリポジトリの概念

| 語                   | 意味                                                                                                                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| procedure            | contract に定義し、server で実装する、API の1つの操作。                                                                                                                                                |
| contract             | `packages/contract` にある、procedure ごとの入力・出力・エラー・パスの定義。「契約」と訳さない。                                                                                                       |
| base                 | アクセス区分ごとに認可を決めてある、procedure を作るときの出発点(`publicProcedures`・`authProcedures`・`deployProcedures`・`adminProcedures`)。                                                        |
| 外部用のポート       | CMS が待ち受ける2つのポートのうち、リバースプロキシを通って、ブラウザからのリクエストを受けるもの(`PORT`)。管理用 API と認証用 API を受ける。                                                          |
| 内部用のポート       | CMS が待ち受ける2つのポートのうち、サーバーの外から届かないもの(`INTERNAL_PORT`)。公開 API とデプロイ用 API を受ける。                                                                                 |
| 公開 API             | 公開しているコンテンツを返す API(contract の `public`)。内部用のポートで受け、公開サイト(Amayadori)のサーバーから呼ぶ。資格情報を求めない。                                                            |
| デプロイ用 API       | 公開サイトのデプロイのときに、client の CLI が種類のデプロイ用 API(contract の `deploy`)。内部用のポートで受け、デプロイ用のトークンを求める。                                                         |
| デプロイ用のトークン | デプロイ用 API を呼ぶための資格情報(概念の名前)。管理者が管理用 API で発行する。`{id}.{secret}` の文字列そのものを指すときは、セッションと同じく token と書く(token を返すのは発行したときの1回だけ)。 |
| 固定ページ           | メタデータ(slug・タイトル・種類・公開状態・並び順・日時)を列に、中身を JSONB に持つページ。About や Colophon など。                                                                                    |
| 破壊的変更           | 既存の固定ページの中身が、新しい種類の定義の検査を通らなくなる変更。CMS は断り、合わないページの一覧を返す。                                                                                           |
| 種類の定義           | 種類の名前と項目の並び。公開サイトのコードで `defineKind` を使って書き、CMS は受け取って DB に持つ。                                                                                                   |
| mapper               | DB の行を contract の出力に変える純粋関数。                                                                                                                                                            |
| 判断する純粋関数     | 変更してよいか、何に変えるか、どのビジネスイベントを出すかを決める純粋関数。service と呼ばない。                                                                                                       |
| DB に触れる関数      | `*.query.ts` に置く、DB を読み書きする関数。repository と呼ばない。                                                                                                                                    |
| dispatcher           | ビジネスイベントを受け取り、キャッシュの無効化や Webhook に配るもの。                                                                                                                                  |
| 公開状態の判定       | コンテンツを公開サイトに見せてよいかを決めること。公開状態を持つ feature の関数だけが行う。                                                                                                            |
| 登録用 URL           | server のコマンド(`bun run passkey:enroll`)が出す、パスキーを登録するための1回きりの URL。最初の登録と、パスキーを全部失ったときの復旧に使う。                                                         |
| 再認証               | ログイン中の管理者に、パスキーの追加と削除と、デプロイ用のトークンの発行の前に、今のパスキーで確かめ直させること。                                                                                     |
| 想定内の失敗         | slug の重複のように、起こりうると分かっていて、`_tag` 付きの判別共用体で返す失敗。                                                                                                                     |
| 想定外の失敗         | throw して、入口で 500 とログにする失敗。                                                                                                                                                              |
| 割り切ったこと       | 実害が無いので、直さずに受け入れると決めた失敗や制限。各 `DECISIONS.md` の末尾の「割り切ったこと」に、起きる条件と直さない理由を書く。                                                                 |
| 適用する             | migration の SQL を DB に流して、DB の形を変えること。                                                                                                                                                 |
| API 越しのテスト     | `src/test-client/` で組み立てたアプリに、client か `Request` で触るテスト。DB の中身を直接見ない。                                                                                                     |
| 理由付きの抑制       | ファイルの1行目に `// oxlint-disable project/max-code-lines -- 理由` を書き、分割の見出しを置いて、コードを800行まで許すこと。                                                                         |
| 分割の見出し         | 罫線・見出しの行・罫線の3行の `//` コメントで、長いファイルを区切るもの。                                                                                                                              |
| コードの行数         | 空行とコメントだけの行を除いて数えた行の数。                                                                                                                                                           |
| フェーズのブランチ   | フェーズや大きなリリースごとに、main から切るブランチ(`phase/<番号>`)。子のブランチの PR を受ける。                                                                                                    |
| 子のブランチ         | フェーズのブランチから切り、小さな課題を作るブランチ。                                                                                                                                                 |
| 観点                 | レビューで見る範囲の単位。観点ごとの依頼文が `tooling/review/prompts/` にある。                                                                                                                        |

## 機械で探す語

`tooling/structure/` のテストが、文書・コメント・文字列から探す表記。コミットのメッセージからは、commit-msg の hook が、探す範囲が「リポジトリ全体」の語だけを探す。部分一致で探すので、ほかの意味ではまず使わない表記と、エージェントが書きがちな言い回しだけを挙げる。バッククォートとかぎかっこの中は探さない。

| 表記                                           | 代わりに書くもの                             | 探す範囲       |
| ---------------------------------------------- | -------------------------------------------- | -------------- |
| 配送役、配信役                                 | dispatcher                                   | リポジトリ全体 |
| 判別子                                         | `_tag`                                       | リポジトリ全体 |
| ログの書き出し口                               | logger                                       | リポジトリ全体 |
| 印を付け、印をつけ、札を付け、札をつけ、札を貼 | 指しているもの(プロパティの名前、値、型など) | リポジトリ全体 |
| 版上げ、版を上げ、版を下げ、版を固定           | バージョン                                   | リポジトリ全体 |
| 埋め草                                         | padding                                      | リポジトリ全体 |
| 理由付きの例外                                 | 理由付きの抑制                               | リポジトリ全体 |
| 指摘すること、指摘しないこと                   | 診断を出すこと、診断を出さないこと           | `tooling/`     |
