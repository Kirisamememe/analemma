# 決めたことと理由(管理画面の画像)

画像は写真作品を兼ねるので、一覧も1枚の写真を見る画面も、写真が主役の見せ方にする(ユーザーと決めた)。server の決めごとは `apps/server/src/features/images/DECISIONS.md` にある。

## 写真の編集

- タイトル・説明・alt のガイドに、保存の検証で使う contract から文字数の上限を表示する。タイトルと説明の placeholder は入力例にし、alt は写真を見られない人に写っているものを伝える用途をガイドで案内する。

## 一覧

- 画像の一部を書き換えても、成否が分からなかった別の操作を確かめるための再取得は保つ。続きを読み込んでいるときはその応答を待ってから反映し、同じページを読み直す手間を防ぐ。

- 画像タブの中では読んだページと元の表示位置を保持する。写真から戻ったときに同じ一覧をすぐ操作できるよう、開いた写真へ focus を戻す。通信できないときも読み込み済みの一覧を表示する。セッション失効の応答が届くか、ほかのタブに移ったら破棄する。

- 写真の縦横比を保ったまま、高さをそろえて行の幅いっぱいに並べる(ユーザーが3つの案から選んだ)。3:2 などに切り抜く格子と違い、縦の写真も構図のまま見られる。
- 並べるのは CSS の flex だけで、JS で幅を測らない。写真ごとに縦横比を `--media-aspect` で渡し、`flex-grow` を縦横比にして、最低の高さ(狭い幅で 7rem、広い幅で 11rem)から行を伸ばす。同じ行の写真は、伸びる割合が同じなので、高さがそろう。縦横比は配信用の画像の幅と高さで読み込む前に分かるので、写真が届いても並びがずれない。
- 写真の下の文字は、枠の幅を広げない(`w-0 min-w-full`)。長いタイトルで行の切れ目が変わらないようにする。
- タイトルが無い写真に alt があれば、リンクの名前に含める。「無題」が並んでも、読み上げで写真の内容を聞き分けられる。
- 最後の行は伸ばさず、左に寄せる(`after:grow-999`)。1〜2枚だけ残った写真が大きくならないようにする。
- 極端な縦横比は、一覧の枠を縦 1:2・横 5:2 に収め、はみ出す分を中央で切る(ユーザーが決めた)。パノラマが細い1行になったり、縦長が細い線になったりしないようにする。1枚の写真を見る画面では切らない。
- 広い幅では、行の高さを最低の高さの 1.5 倍で止め、超える行だけ写真の上下を少し切る。行の切れ目は前から順に決まるので、次の写真が入らずに残った幅が大きいと、その行だけが高くなる。狭い幅では止めない。1枚で全幅になる行が多く、止めると写真の半分ほどを切ってしまう。
- img の `sizes` は、縦横比と最低の高さから、よくある伸び方(広い幅で 1.2 倍、狭い幅で 2 倍)を見込んで書く。`sizes="auto"` は WebKit が対応していないので使わない。見込みより伸びた行では、写真が少しだけ粗くなりうる。
- 配信用の画像がまだ無い画像は、写真の代わりに、3:2 の枠にアイコンと文言を出す。
- 読み込む間は、写真の形の灰色の枠を並べ、読み上げには文言だけを渡す。
- タイトルが無い画像は「無題」を薄く出し、非公開の画像にだけ「非公開」のバッジを付ける(既定は公開なので、公開のバッジは並べない)。撮影日が分かれば日付を出す。
- 続きは「さらに読み込む」で50件ずつ足す(管理用 API の cursor)。足したら、足した最初の写真に focus を移す。押したボタンが最後のページで消えても、focus が文書の先頭に戻らず、キーボードで続きから見られる。続きを読めなければ、読んだ写真を残したまま、その下に読み込めなかった欄を出して取り直せるようにする。
- 1枚の写真を見る画面への行き先は、一覧を置く画面(route)から受け取る。feature が route のパスを知らずに済み、固定ページの一覧と同じ分け方になる。

- 写真は選んだ順に、1画面で2枚まで並行して送る。server が1枚を変換している間に次の写真を受け取れるため。
- server の受付が埋まっていて 503 を受けた写真は、失敗にせずに待機へ戻す。server は本文を読む前に断るので、登録していないことが確かで、送り直しても二重に登録されない。その後の10秒(server が添える `Retry-After` と同じ)は、写真を足しても送り直しても新しく送らず、送っていた写真が終わって空いた枠でだけ1枚送る。10秒たったら、2枚で送り直す。503 が12回(約2分。server が1枚の変換を待つ時間)続いた写真は、送れなかったことにする。すぐ失敗にすると、ほかのタブの送信や、読み込み直す前の送信が受付を1つ持っているだけで、待ちの写真が続けて失敗になり、1枚ずつ送り直すことになる。
- 写真の送信中もタイトルと説明を入力できる。「完了」で、追加できた写真のうち入力が変わったものを保存する。画像の更新 API は alt を含む全欄を受け取るため、保存直前に最新の値を読み、入力した欄だけを重ねる。途中で失敗したら入力を保ち、次の「完了」では保存済みの写真を飛ばす。
- 追加できなかった写真のうち、送り直せる写真か、入力のある写真があるときは、「完了」の前に枚数を示して確かめる(ユーザーが決めた)。黙って片付けると、送り直す機会と入力を知らないうちに失う。「戻る」なら写真と入力を保ち、「破棄して完了」なら、追加できた写真の入力を保存してから、追加できなかった写真をすべて片付ける。形式や大きさで追加できなかった写真だけで、入力も無いときは、確かめずに完了する。できる操作が残っていないため。
- この確かめは、画面を離れる前の確かめと同じ Dialog の部品で出し、状態は別に持つ。画面を離れる前の確かめは router の移動を止める仕組みで、「完了」は移動ではない。

- 選択とドロップは同じ Dialog を開く。転送中は、各写真の上にそのリクエストの転送率を重ねる。受け付けたファイルを server が登録したら、写真をアップロード済みとして一覧に加える。ファイル名と送信状態は写真の下に置き、全体の状態は入力欄の下の Notice にアイコンと件数の1行で示す。失敗が残ったときは、写真を選ぶとその写真に対してできる操作が分かる。

- `useUploadDialog()` の返り値は1つの変数で受け、JSX の `ref` に渡すもの(`attach`・`attachPanel`・`focus.addButton`)だけを、先に1つずつ取り出す(ユーザーが決めた受け方)。`ref` に渡した値を持つオブジェクトのほかの値を描画中に読むと、lint の `react/refs` が ref の読み取りと見なす。`ref` に渡すものを1つのオブジェクトにまとめる形でも通らない。

## 写真をドロップする領域

- 画像一覧を開いている間は、本文とその上に開いた Dialog のどちらでもファイルを受け取る。一度に落としたファイルを元の順序でまとめて渡す。
- 案内を本文の上に重ねるときは、画面の切り替えに伴って動く領域の外に描く。枠と案内はポインタの入力を背後に通し、写真を重ねたまま別の子要素に移動しても表示を保つ。

## 1枚の写真を見る画面

- 写真を送る間は、3つの操作を同じ fieldset で止めてボタンの色と位置を保つ。Dialog と送信先は操作を始めた画像に固定する。

- 一覧へ戻るリンクを「一覧へ」とし、狭い画面では操作ボタンを一段小さくする。文字を拡大したときは、帯を折り返してボタンの文言を1行に保つ。

- 次の写真と情報を待つ間は、表示している写真の矢印を残して移動を止める。同じ矢印を続けて押しても、まだ見ていない写真を飛ばさないため。写真が替わったら情報欄の先頭を表示する。
- 一覧は `/images`、1枚の写真を見る画面は `/images/$id`。写真を見る画面は、写真を大きく出すため、ナビの骨組みの外に置き、セッションは、ナビのある画面と同じように、画面を開くときに裏で確かめる。写真を直接開く場合にも、確認の応答を待たずに描き始める。一覧から開くときに共通の `PageTransition` を使う。写真を送るときは ID の降順に合わせ、次は右から、前は左から写真だけを出す。画像を読み終えてから動かし、動きを減らす設定では切り替えるだけにする。
- キーボードで写真を送った後は同じ方向の矢印に focus を戻す。写真の明暗に左右されず見分けられるよう、矢印の暗い面の内側に明るい focus ring を描く。端では反対の矢印、前後とも無ければ一覧へ戻るリンクを使う。待つ間に自分で動かした focus は保つ。
- 写真を見る画面は、管理画面の配色によらず暗い配色(`scheme-dark`)にし、写真を大きく出す(ユーザーが3つの案から選んだ)。写真の色を、周りの明るい面に引っ張られずに見るため。
- 広い幅では、写真の右に情報の欄を置く。狭い幅では、写真の下に置く。ブラウザが表示幅に見合う画像を選べるよう、48rem 以上のときの img の sizes は情報の欄の幅(22rem)と写真の左右の余白(合計 3rem)を引く。
- 写真の情報を取得する間も一覧に戻れるよう、上の帯を先に出す。写真と情報の欄の位置には骨組みを置き、短い待ち時間は共通の読み込み表示と同じく描かない。
- 画像ファイルの取得中は画像の表示寸法を保ち、標準の切り替え時間が過ぎてから読み込み中の表示を出す。キャッシュからすぐに読める写真で表示が一瞬だけ出るのを防ぐ。配信に失敗したときは手動で再試行できる。
- 高さが20rem以下になると上の帯の固定を外す。拡大表示や横向きの低い画面でスクロールしたとき、focus 中の矢印が帯に隠れないようにする。
- 前後の画像へは、写真の左右のボタンで移る。ボタンは、ポインタを載せたときと、キーボードで focus したときに出す。タッチでは、写真をタップするとボタンが現れる。左右のスワイプでも移れる(ユーザーが決めた)。スワイプは、横に 48px 以上、縦の 1.5 倍以上を、0.8 秒以内に動かしたときだけにし、縦の scroll と拡大は残す(`touch-pan-y touch-pinch-zoom`)。
- 情報の欄には、タイトル・公開状態・足した日時・説明・alt・撮影の情報を出す。説明と alt は、無ければ出さない。撮影の情報は分かる値だけを出し、1つも無ければそう書く。
- 前後は、一覧と同じ並び(新しく足した順)で、管理用 API の `neighbors` から読む。一覧で読み込んだ範囲に依存せず、URL の画像 ID をもとに隣の画像を取得するため。一覧へ戻るリンクと前後の行き先は、写真を見る画面(route)から受け取る。
- 短いシャッター速度は写真でよく使う分数にし、1/4 秒より長い露光は小数にする。配信用の画像の alt が未設定なら、写真を見つけられるよう詳細ではタイトルを画像の名前に使う。タイトルもなければ無題と伝える。

- 編集(タイトル・説明・alt)は Dialog で行う(ユーザーが決めた)。編集する欄が3つで、写真を見る画面を離れずに入力できるため。編集を開くたびに現在の値を取得し、別のタブで保存した値が古いキャッシュで上書きされないようにする。未保存の入力を閉じるときや画面を離れる前は、破棄してよいか確かめる。空の欄は null で送り、前後の空白は落とす。誤りは、パスキーの名前と同じく、送った後から欄に出す。
- 保存中に別の写真へ移るときは、送った保存が続くことを伝える。元の写真では保存が済むまで編集を開けず、移動の確認中に保存が済んだり、写真が既に削除されていたりしたら、編集を閉じて頼まれた移動を続ける。
- 上の帯に、一覧へ戻るリンクと、編集・公開と非公開・削除を置く。390px の幅でも1行に収まる。変換を終えていない画像(変換中・変換できなかった画像)には、公開と非公開の操作を出さない(server も断る)。編集と削除は出す。

- 公開はその場で送り、非公開は閲覧できる人が変わるので、対象の写真の名前を Dialog に出して確かめる。成功は Toast で知らせる。削除は物理削除で戻せないので、名前を見せる Dialog で確かめる。
- 書き換えと公開と非公開の応答には、取得と同じ形の画像が返るので、取り直さずにキャッシュを差し替える。一覧は画像タブを開いている間、読み込んだ全ページを保持する。編集・公開状態の変更は該当する画像でその操作が変えた欄だけを更新し、削除は該当する一件を外す。成否が分からないときだけ裏で取り直す。別のタブに移ったら一覧と表示位置を破棄する。公開状態の変更や削除で画像がもう無いと分かったら、その応答を詳細に反映する。編集中にほかのタブで削除した写真は保存できないので、Toast で知らせて編集を閉じる。

- 同じ画像の書き換えは応答を反映するまで順番に送る。画面を開き直して次の保存を始めた場合も、先に送った保存の応答で新しい入力を上書きしない。削除した画像をまだ開いていれば、一覧の該当行を外してから一覧に戻る。隣の写真を表示中であれば、その位置で前後だけを取り直す。

## 送る写真のプレビュー

- 複数の写真は元の縦横比で横一列に並べ、選択した写真を前後のボタンと矢印キーで切り替える。選択した写真を列の内側に表示し、画像があとから読み込まれて幅が変わったときも選んだ位置を保つ。
- 選んだファイルは Blob URL で表示し、プレビューから外れたら解放する。ブラウザが元の形式を表示できないときは、アップロード後の配信用の画像で同じ位置を更新する。

- 送信中の写真には、転送率を円弧で重ねる。明るい写真の上でも白い線を読めるよう、転送中の写真だけを暗くする。選ぶボタンと進捗は隣り合う要素にし、選択を移しても転送中のファイル名と割合を読み取れるようにする。

## 写真を選ぶボタンと送信状態

- 破線のボタンにファイルの形式と上限を載せ、同じ説明をボタンから参照する。ファイル選択から戻ったら input を空に戻し、同じ写真も選び直せるようにする。
- 送信結果は選択中の写真の名前に添える。アップロード済みの写真は名前を詳細画面へのリンクにし、送り直し後の focus もそのリンクへ移せるようにする。

## 再レンダリングの期待

頻繁に変わる state は、写真の転送率と、送る写真のタイトルと説明の入力。件数に比例して増える部品は、一覧の写真と、カルーセルの写真。

- 一覧は API の1ページごとに `memo` で包む。続きを読み込む間や、足した写真に focus を移すときに、表示済みの写真と日付を再レンダリングしない。写真を送っている間も、一覧を再レンダリングしない(`upload/__tests__/photo-uploads-rendering.test.tsx`)。
- 転送率は送信試行ごとに持ち、その写真のリングだけが購読する。並列で送っても、別の写真のリングとプレビューを再レンダリングしない。再送の後に前の試行の通知が届いても、新しいリングの値は変わらない。キューは、送信の開始・成否など、写真の状態が変わったときにだけ更新するので、転送率の通知では Dialog とカルーセルを再レンダリングしない(`upload/__tests__/upload-carousel.test.tsx`・`upload/__tests__/photo-uploads-rendering.test.tsx`)。
- 入力は選択中の入力欄だけが購読し、完了や画面を離れる操作では、その時点の入力を読む。1文字入力しても、Dialog・カルーセル・もう一方の入力欄を再レンダリングしない。選び直しても、写真ごとの未保存の入力を保つ(`upload/__tests__/photo-uploads-rendering.test.tsx`)。
- 写真を編集する Dialog の入力は、TanStack Form が欄ごとに購読する。ビューアの state(操作の表示、写真の読み込み)は、写真1枚の中で閉じ、件数に比例しないので、テストを求めない。

## 割り切ったこと

- **セッションが切れた後の送信**。セッションが切れた後に 1 MB を超える写真を送ると、server はセッションの無い送信をほかの API と同じ上限で断るので、`UNAUTHORIZED` ではなく 413 が返り、写真は送れなかったことになる。待ちの写真も続けて送れなかったことになり、一覧の取り直しが `UNAUTHORIZED` を受けてログインの画面へ移る。ログインし直せば選び直して送れ、登録済みの写真は失われない。写真の送信で見分けるには、本文を読む前にセッション切れを返す応答の形を server に足す必要があるので受け入れる。
- **ログアウトしたときの、送っていない写真**。写真を送り終える前や、送れなかった写真を残したままログアウトすると、確かめずにログインの画面へ移り、送っていない写真と入力は失われる。ログアウトは管理者が自分で選ぶ操作で、登録済みの写真は残るので受け入れる。
- **応答を受け取れなかった写真の送り直し**。通信が切れて応答が届かなかった写真は、server が登録していても「送れませんでした」と出る。送り直すと同じ写真が2つ公開される(server の images の `DECISIONS.md` の「割り切ったこと」)。失敗の後に一覧を取り直すので、Dialog を閉じれば登録済みかを確かめられる。
- 配信用の画像の URL があっても、通信が途切れてサムネイルを読めないことがある。タイトルから写真を見る画面を開くか、一覧を読み込み直せる。タイルごとにファイルの読み込み状態と再試行の操作を持つほどの影響はないので、一覧には専用の再試行を置かない。
