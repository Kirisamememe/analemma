# 画像を選ぶ Dialog

- 写真の配置、続きを読み込む操作、取得に失敗したときの再試行は画像の一覧と共有する。Dialog は別の query のキーを使い、画像の画面に戻るために保持するページとスクロール位置に影響させない。
- 1枚を選ぶときはラジオボタン、複数枚ならチェックボックスで写真を選ぶ。追加済みの画像は選択数に含めない。選択を確定した時点で呼び出し元に画像を渡すので、キャンセルで編集中の値を保てる。

- 表紙を選び直すときは現在の画像で選択を始め、フッターに選択中のタイトルを表示する。現在の表紙が Dialog を開いた後に届いたときは、未操作なら初期値として表示し、すでに選び直した写真は保持する。写真全体を見比べられるよう、1枚を選ぶ一覧では元の縦横比を使い、選択の印を写真に重ねる。

## 変換中の画像

- 写真は、受け取りと変換が別に進む。一覧と写真の画面は、画像の状態(変換中・変換できなかった理由・非公開・公開)から、バッジと、写真の場所に出す文言を決める(`logic/image-status.ts`)。 一覧のタイルには短い状態の文言だけを出し(読み取れなかったか、変換できなかったか)、理由と次にすることまで書いた文は、写真の画面に出す。変換できなかった画像は、理由(写真を読めない・server の都合)を写真の場所に書き、送り直して直るかどうかを伝える。
- 変換が終わったことは、変換中の画像を取り直して知る(`hooks/use-conversion-polling.ts`。2秒おき)。取り直しは、画像を読む取得(`hooks/use-image.ts`)とは別のキーで流す(`apps/admin/DECISIONS.md` の「features の依存」)。画像を読む hook は、読んだ画像が変換中の間だけ取り直しを流す。一覧は、読み込んだ変換中の画像のうち、いちばん先に受け取った1枚だけを取り直し(`hooks/use-conversion-watch.ts`)、一覧そのものは読み直さない。server は変換を1枚ずつ進めるので、たいていはその1枚が次に終わる。並べて送った写真は順が入れ替わることがあり、そのときは、後の写真の結果が出るのが、先の写真が終わるまで遅れる。変換中の画像が無ければ、何も取り直さない。
- 取り直しに失敗しても、取得できるまで取り直し続ける。止めると、通信が戻っても一覧が変換中のまま残る。取り直した画像が無くなっていたら(別のタブで消したなど)、読み込んだ一覧から外して、次の変換中の画像へ進む。
- 取り直した画像が変換を終えていたら、読み込んだその画像と、読み込んだ一覧のその画像の、状態・公開した日時・配信用の画像だけを差し替える。変換中のままなら、どちらのキャッシュにも触れない。タイトルや説明は差し替えない。保存の応答より遅れて届いた取り直しの結果が、保存した値を古い値に戻さないようにする。
- 写真の画面は、状態のバッジと、写真の場所に出す文言を `output` に入れ、変換の結果を読み上げにも知らせる。

- 一覧は、変換を終えたことと、変換できなかったことを、読み上げに知らせる(「「タイトル」の変換が終わりました」)。変換を待つ画像がある間から、最後に変換を終えた結果を出した後まで、画面に出さない知らせの欄(`Announcement`)を置き、変換中だった画像の状態が替わったら文言を入れる。無題の画像が続くと同じ文言になるので、知らせるたびに中の要素を作り直し、同じ文言でも読み上げに伝わるようにする。写真を追加する Dialog が知らせるのは開いている間だけで、閉じて一覧に戻った後の変換の結果は、一覧でしか知らせられない。知らせるのは、取り直しを購読する部品(`ConversionWatch`)で、一覧とタイルは巻き込まない。固定ページの画像の欄は、選んだ画像の状態が替わっても知らせない(バッジと文言は替わる)。

## 再レンダリングの期待

頻繁に変わる state は、画像の選択と、変換中の画像の取り直し(2秒おき)。件数に比例して増える部品は、一覧のタイル。

- 選択状態は Dialog を開いている間だけ保持する。入力欄は自分の画像が選ばれているかを、フッターは、選択中の画像のうち、追加済みと削除済みを除いた枚数を購読する。1枚を選択・解除しても、ほかのタイルと Dialog を再レンダリングしない(`hooks/__tests__/use-image-choice.test.tsx`)。

- 変換中の画像を取り直している間は、取り直しが失敗し続けても、一覧もタイルも再レンダリングしない。取り直しは、呼ぶ側に何も知らせない(`useApiPolling`)。変換を終えたときは、その画像のタイルだけを再レンダリングする(`__tests__/images-section.test.tsx`)。

- 固定ページの画像の欄で、変換中の画像を選んだまま画像を選ぶ Dialog を開いているときも同じにする。欄は選んだ画像を取り直すが、取り直している間は、取り直しが失敗し続けても、欄も Dialog も再レンダリングしない(`hooks/__tests__/use-image.test.ts`)。Dialog は、最初に選ばれている画像を ID で控え、同じ画像の内容が変わっても、選択を配る context の値を変えない(控え直すのは、開いた後に画像が届いたときと、別の画像に替わったときだけ)。変換を終えたときに再レンダリングするタイルは、その画像の1枚だけ(`features/fixed-pages/editor/__tests__/image-field-conversion.test.tsx`)。

## 割り切ったこと

- **取り直しに失敗している間の表示**。通信が切れるか server が止まって、変換中の画像を取り直せない間も、一覧・写真の画面・固定ページの画像の欄は「変換中」のまま出し、取り直せていないことは知らせない。その間はほかの操作も失敗として伝わり、通信が戻れば自動で取り直して結果が出る。取り直しの失敗を画面に出すには、取り直しの状態を読む側に配る必要があり、知らせても管理者にできることが待つことだけなので、受け入れる。
- **取り直しで無くなったと分かった画像の選択**。画像を選ぶ Dialog で変換中の画像を選んだ後、別のタブでその画像を消すと、一覧からは消えるが、選択には残り、確定すると無い画像の ID が固定ページに入る。固定ページは、使っている画像が消えることを前から許していて、編集画面は無い画像として出し、公開サイトは取れないときの表示に切り替える。2つのタブで同じ画像を選びながら消したときだけ起きるので、受け入れる。
